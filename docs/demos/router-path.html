Path routing

Real paths, no #. The address bar reads /users/7 and the history entry is a normal URL — but the server has to cooperate: any unmatched path must return this document, or a refresh 404s.

Things to try — including the failure mode

  • Click the links: the path changes with no #, and back/forward work.
  • Type into the shell input, then navigate — it survives, same as hash mode.
  • Now press reload on a deep link. On a static host with no rewrite rule this 404s — that is the trade-off, and the reason hash mode exists. GitHub Pages serves a 404 page, so this site ships a fallback that bounces you back here with the path intact.

Making it work on a real server

// Express
app.use(express.static('public'))
app.get('*', (_, res) => res.sendFile('public/index.html'))

# nginx
location / { try_files $uri $uri/ /index.html; }
